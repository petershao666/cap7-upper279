# Seven-dimensional cap sets: upper bound 274

This release packages the exact proof that every cap in `F_3^7` has at most **274 points**, using the explicit low-dimensional mathematical premises below. Together with the previously verified 236-point construction, the accepted interval is `236 <= f(7,3) <= 274`. It does not determine the maximum or settle the existence of a 237-point cap.

The main mathematical argument is [PROOF.md](workspace/research_2026-09-05-upper274-continuation-r2/root_audit/global274/PROOF.md). The final coefficient packet has SHA-256 `78238a2e3f389f9c7a4f93e049ad56e678c09103151fb3bfed0adc6e1dcf14bf`. The last contradiction is the exact positive integer `364 K - U = 148616699075`.

## Portable verification

From the repository root, using Python **3.9 or later**:

```sh
python3 upper274/verify_release.py --mode quick
python3 upper274/verify_release.py --mode final
```

`quick` is the default. It checks every byte-preserved source against `SOURCE_MANIFEST.json`, then reruns the frozen exact global integration: all 341 sorted size-275 profiles, all 56 negative profiles, completion-state partitions, inherited certificate gaps, and all eight continuation closures. It compares the generated global report with the frozen report.

`final` includes `quick`, then freshly builds and runs both final C++17 verification kernels with undefined-behavior sanitization. It checks 7,701,024 lower/outer raw matrix rows and 1,106,094 NC106 raw rows (8,807,118 total), regenerates the 14 NC106 domains and requires byte-for-byte equality, and reruns the separate standard-library Python support audit (15,885 support/conditional evaluations and 143 summed case bounds). The exact case records and final contradiction must match the frozen records. This mode requires a compiler supporting signed `__int128` and the undefined-behavior sanitizer, such as a suitable Clang or GCC installation. Use `--compiler clang++` or `--compiler g++` if needed. Optimizers and numerical libraries are not needed for either mode. The release-preparation run took about 1 second for `quick` and 17 seconds for `final` on the preparation machine, including compilation; these are observations, not runtime guarantees. Other compilers and hardware may take longer.

Generated reports go into a fresh temporary directory whose path is printed. To retain them at a chosen location:

```sh
python3 upper274/verify_release.py --mode final --output /tmp/cap274-review
```

The specified output directory must not already exist and must be outside this package. All research scripts that write reports run in a separate temporary copy. The frozen package is never modified. Do not run Python with `-O`: historical exact checkers use assertions, and the entry point rejects optimized Python execution.

## What is, and is not, replayed

| Layer | Release mode behavior |
|---|---|
| File integrity and global implication | Rerun in `quick` and `final` |
| Last lower40 / outer and NC106 finite domains | Fresh compilation and exhaustive replay in `final` |
| NC106 domain generation and finite support algebra | Rebuilt/recomputed in `final` |
| Original upper-275 baseline, first-round 88 certificates on 153,548,040 rows, first seven continuation closures | Accepted historical exact audit evidence, hash-bound and supplied; their large domains are not all rerun by these modes |
| Earlier actual16/17 classification enumerations and recovered complete41 inputs | Accepted frozen families, derivations, coordinates, source/replay records; not fully regenerated by these modes |
| Published classification and completion theorems | External mathematical premises; their original classification searches are not independently reproved |

**Neither mode is a complete proof from scratch.** Source integrity alone is not mathematical verification. The global implication depends on the supplied geometric reductions, the accepted earlier finite-domain audits, and the stated published theorems. A fresh execution of a previously independent kernel is a replication of that kernel, not another independently implemented checker. All implementations share the frozen coefficients and accepted classification data. The support audit separately implements finite sums, but it shares those inputs and used the earlier checker schema.

The earlier author's upper-275 `README.md` records a then-partial Python run. The subsequent independent audit completed both implementations; see the included [upper-275 audit](workspace/audit_2026-09-05_upper275/AUDIT.md). Preserve that historical distinction rather than rewriting original sources. Likewise, historical reports saying "upper bound remains 275" describe the stage at which they were created. The final upper-274 report supplies the integrated conclusion.

## Mathematical premises and sources

The detailed baseline statements D1–D6 and exact source locations are preserved in the [baseline input list](workspace/audit_2026-09-05_upper275/cap7_upper275/baseline277/baseline278/README.md). They include:

- The dimension-four bound 20; the dimension-five bound 45 and affine uniqueness; classification/completion of large dimension-five caps, including the exceptional 42-point class.
- The dimension-six bound 112 and affine uniqueness, and the published 110-to-112 completion theorem. Later derived completion rules retain their separate proofs and scope.
- The stated reflected-slice propositions and low-dimensional profile restrictions; no minimum-only seven-dimensional closure is used as an ordinary prohibition.
- For the complete41 support family, Thackeray's Theorem 6.3 **and the explicit ancillary-list coverage assertion in Proposition 6.2(b)**. Checking recovered representatives does not independently establish the completeness of that published search. The [complete41 proof](workspace/research_2026-09-05-upper274-continuation-r2/root_audit/complete41/PROOF.md) maps all 13 source alternatives to the 44 accepted histograms.
- The 376 actual16 and 102 actual17 histogram families, the 17 relevant 18-point states and the capacity table, with their stated complete-cover derivations and accepted independent finite checks. They are used only in their proved dimension and physical-column scope.

Primary sources are Aaron Potechin, [*Maximal caps in AG(6,3)*](https://doi.org/10.1007/s10623-007-9132-z); Henry (Maya) Robert Thackeray, [*The cap set problem: 41-cap 5-flats*, arXiv:2206.09719v1](https://arxiv.org/abs/2206.09719v1); and Thackeray, [*The cap set problem: Up to dimension 7*, arXiv:2206.09804v1](https://arxiv.org/abs/2206.09804v1). The two arXiv documents are cited as public preprints. No independent reproof of their classification searches, publication-priority claim, or peer-review claim is made here.

## Package layout and historical paths

`workspace/` preserves the original relative layout of the selected proof dependencies:

- `audit_2026-09-05_upper275/`: baseline and completed independent audit;
- `research_2026-09-05-capset-round1-r1/`: upper-bound route and its accepted independent checks;
- `research_2026-09-05-upper274-continuation-r2/`: exact branch certificates, support families, proof maps, verification sources, and selected frozen replay evidence;
- `audit_2026-09-06_upper274/`: post-proof independent replication record and support audit.

`SOURCE_MANIFEST.json` lists the original relative source, byte count, hash, and inclusion role of every frozen file. Historical source files, inventories and logs are byte-preserved, so they may contain the original machine's absolute paths. These strings are historical provenance, not runtime prerequisites. The portable entry point resolves all active inputs inside this package. Only the support-audit adapter makes three narrowly scoped in-memory substitutions: input root, output root, and historical absolute hash-path resolution. It does not change arithmetic, coefficients, checks, or frozen source bytes.

This is a selected proof/replay closure, not a dump of the research workspace. Compiled executables, optimizer caches, large redundant generated discovery tables, whole third-party papers/archives and unrelated research are omitted. Some historical manifests therefore mention omitted regenerable or externally sourced files; they remain historical inventories, not promises that every historical discovery pipeline is executable from this release. All inputs read by the advertised portable modes are included and hash-checked. Frozen coefficients, accepted finite support data, mathematical derivations, earlier verification sources and their exact acceptance records are retained. Consult [REVIEW_AND_NEXT_PLAN.md](workspace/audit_2026-09-06_upper274/REVIEW_AND_NEXT_PLAN.md) for the explicit acceptance boundary of the post-proof audit.
